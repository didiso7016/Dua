# 部署與交接

## 本機與線上分開
本機使用 Worker 模擬、D1 SQLite 與 R2 本機儲存，不需要連接正式資料。setup:local 僅使用 --local，不接觸正式資料庫。保留 .dev.vars 與 .wrangler/state 才能保有本機帳號及上傳內容。

## 執行環境
Node.js 24、pnpm 11.25.0；Cloudflare Worker 相容環境、DB（D1）與 BUCKET（R2）bindings。不是一般 PHP 或純靜態網站，不能單靠 Live Server 啟動。

- 設定集中在 wrangler.jsonc（Worker 名稱、D1、R2）與 vite.config.ts；Worker 進入點是 worker/index.ts。
- 本機：`pnpm install --frozen-lockfile` → `pnpm setup:local` → `pnpm dev`（http://localhost:5173）。
- 檢查：`pnpm typecheck`、`pnpm test`、`pnpm build`；`pnpm start` 以 wrangler 在本機跑建置後的版本。
- 原本 ChatGPT Sites 的 .openai/hosting.json、build/ 外掛與 Sites 安裝腳本已移除（git 歷史可還原）。

改部署到公司自己的 Cloudflare 帳號時：建立正式 D1 與 R2，把 wrangler.jsonc 的 database_id、bucket_name 換成正式值（binding 名稱 DB／BUCKET 不變），套用 drizzle/ 的 migration，用 `wrangler secret put` 設定下方環境變數，再 `pnpm build` 後部署。不要將本機 placeholder ID 當成正式 ID。

## 環境變數
| 名稱 | 用途 |
|---|---|
| DUA_AUTH_PEPPER | 密碼雜湊秘密；正式備份時須保留 |
| DUA_INITIAL_PASSWORD_HASH | 初始帳密雜湊；初次建帳後使用資料庫帳號 |
| DUA_ADMIN_USERNAME | 初始管理者帳號 |
| DUA_RESET_EMAIL | 管理者密碼重設信箱 |
| DUA_SITE_ORIGIN | 站點來源，正式環境使用 HTTPS |
| DUA_MAIL_API_KEY | 選填，Resend 寄信密鑰 |
| DUA_MAIL_FROM | 選填，已驗證寄件地址 |

正式服務不要使用測試密碼；本機 setup 不會覆蓋已存在的帳號或密鑰。修改初始雜湊不會取代資料庫內已建立的密碼。

## 備份與正式交接
需另行備份 D1、R2 與執行環境秘密。本壓縮檔只含來源與提供的靜態素材，不是線上資料快照。Google Apps Script、試算表權限與寄信服務亦需由公司帳號管理。

## 常見問題
- 無法連 localhost：確認 pnpm dev 持續執行，使用終端機實際印出的埠。
- Authentication not configured：先執行 pnpm setup:local，再重啟 dev。
- no such table：完成本機初始化，確認使用同一資料夾與儲存路徑。
- 密碼無效：既有本機帳號不會因重新 setup 被改回；請勿任意刪除 pepper。
- pnpm 無法執行：先確認 Node／pnpm 安裝；Windows PowerShell 執行原則阻擋時，可在 VS Code 選用 Command Prompt 終端機。
- 本機修改未出現在正式站：這是預期行為，正式部署需另外進行。
