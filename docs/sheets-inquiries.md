# 洽詢名單寫入 Google Sheets（2026-11）

「聯絡我們」頁（/contact）與全站洽詢彈窗送出的資料，會先存進 D1 的 `inquiries` 資料表，再透過**原本預約用的同一個 Apps Script 接收入口**寫入公司名單總表的「洽詢名單」分頁。

- 新動作：`action: 'inquiry'`（原本的 `ping`、`deliver` 不變）。
- 寫入位置：公司名單總表（後台「名單接收設定 → 公司名單總表」的網址；未填時用預設 `1ZQYgbmrqUSYPbvK24DuD4MHRotpu82Kb08Ls6OKDsNI`）。只寫總表，不寫建案專用表。
- 分頁名稱：`洽詢名單`
- 標題列（第 1 列，順序與文字必須完全一致）：

| A | B | C | D | E | F | G | H | I |
|---|---|---|---|---|---|---|---|---|
| 編號 | 時間 | 類型 | 姓名 | 電話 | Email | 公司 | 內容 | 來源頁 |

- 類型會寫入「一般洽詢」或「合作洽詢」；電話、編號存成文字；以 `= + - @` 開頭的內容會加上 `'` 避免被當成公式。
- 防重複與重送：與預約相同。網站先保存，再取得 60 秒租約送出；Google 端以 ScriptLock＋編號比對避免重複列。失敗的名單保持「待補送」，可在 `/admin/sheets` 按「補送未完成名單」（預約與洽詢各最多 5 筆／次）。
- 後台查看：`/admin` 左側「洽詢名單」，可切換 全部／一般洽詢／合作洽詢，並顯示每筆是否已寫入試算表。

> 接收程式碼的原始檔在 repo 的 `lib/google-sheet-script.ts`，後台 `/admin/sheets` 的「複製接收程式碼」就是這份內容。

## 需要你在 Google 端做的事（一次）

### 1. 在公司名單總表新增分頁
1. 開啟公司名單總表（目前為 https://docs.google.com/spreadsheets/d/1ZQYgbmrqUSYPbvK24DuD4MHRotpu82Kb08Ls6OKDsNI/edit ，或後台填的網址）。
2. 左下角「＋」新增工作表，命名為 **洽詢名單**（全形文字、前後不要有空白）。
3. 在第 1 列 A1～I1 依序輸入：`編號`、`時間`、`類型`、`姓名`、`電話`、`Email`、`公司`、`內容`、`來源頁`。
   - 也可以略過這步：新版程式在找不到分頁、或第 1 列整列空白時會自動建立分頁與標題列。但如果第 1 列已有其他文字且不一致，會拒絕寫入（避免寫錯欄位）。
4. 建議：檢視 → 凍結 → 1 列。

### 2. 貼上新版接收程式碼
1. 以管理者帳號登入網站後台 → 「名單接收設定」→「Google Sheets 串接與補送」（`/admin/sheets`）。
2. 按「複製接收程式碼」。
3. 開啟原本那個 Apps Script 專案（https://script.google.com/home → 之前建立的專案）。
4. 打開 `Code.gs`，**全選刪除**後貼上剛複製的新版程式碼，按儲存（磁碟圖示或 Ctrl+S）。
5. 指令碼屬性 `DUA_TOKEN` **不用改**（專案設定 → 指令碼屬性，維持原值）。
6. （建議）上方函式選單選 `authorizeSheets` → 執行。它會檢查兩份表的「預約名單」分頁，並確認／建立總表的「洽詢名單」分頁。如果跳出授權視窗，依指示允許。

### 3. 發布新版本（網址不變）
1. 右上角「部署」→「**管理部署作業**」。
2. 選取現有的網頁應用程式部署 → 右上鉛筆圖示「編輯」。
3. 「版本」下拉選 **新版本**（可填說明：新增洽詢名單）。
4. 執行身分維持「我」、存取權維持「所有人」→ 按「部署」。
5. 部署網址（/exec 結尾）會維持不變，網站後台**不需要**重新填網址或金鑰。

> 注意：不要用「新增部署作業」，那會產生新的網址；若真的用了，需把新網址與原金鑰重新存到 `/admin/sheets`。

### 4. 驗證
1. `/admin/sheets` 按「測試入口連線」，應顯示連線成功。
2. 開前台 `/contact`，用虛構姓名與電話送出一筆「一般洽詢」，再從 `/partner` 的「填寫合作洽詢」送出一筆「合作洽詢」（公司名稱必填）。
3. 確認總表「洽詢名單」多兩列，時間為台灣時間、電話開頭的 0 沒被吃掉。
4. 後台「洽詢名單」兩筆都顯示「已寫入」。若顯示「待補送」，多半是 Apps Script 尚未發布新版本，完成步驟 3 後到 `/admin/sheets` 按「補送未完成名單」。

## 資料庫 migration
新資料表在 `drizzle/0001_inquiries.sql`。部署前需套用到正式 D1：

```
wrangler d1 migrations apply dua-plus-db --remote
```

若正式 D1 當初是用 `wrangler d1 execute --file` 手動建立 0000（沒有 `d1_migrations` 紀錄），上面的指令會嘗試重跑 0000 而失敗；這種情況改為只執行新檔：

```
wrangler d1 execute dua-plus-db --remote --file drizzle/0001_inquiries.sql
```

未套用前，洽詢表單會回傳「暫時無法完成操作」，其他功能不受影響（後台補送按鈕也需要此資料表）。

本機開發執行 `pnpm setup:local` 會依序套用 drizzle/ 內所有 migration（可重複執行）。
